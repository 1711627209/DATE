## 0. 桌面端执行说明（先读这段）

1. **每个项目跑一轮**，一轮 = 6个Agent。串行：青光眼泳镜跑完 → 审核 → 再跑下一个。
2. **Agent 1-4 可并行**（互相独立），**Agent 6 最后跑**（需要前5个的输出做综合）。
3. 把下面每个Agent的"复制这段"整块喂给一个子Agent。`{{项目名}}`、`{{核心搜索词}}` 等占位符按第7节的"首跑输入包"替换。
4. **工具依赖**：Agent 1/2/4/5 需要联网搜索（WebSearch）+ 浏览器（Playwright MCP）。Agent 3/4 主要靠知识库+选装联网。
5. **产出**：每个Agent输出一个结构化段落 → 汇总进 `研究报告v0.2` 文件（第4节模板）。

## 1. Agent团队总览

| # | Agent | 类型 | 回答你6项需求的哪一项 | 工具 |
|---|-------|:--:|------|------|
| 1 | **竞品情报官** | 🔴核心 | ① 竞品分析 + 产品坟场 | 联网+浏览器 |
| 2 | **医学文献官** | 🔴核心 | ③ 医疗技术支撑（论文） | 联网+PubMed/知网 |
| 3 | **硬件BOM官** | 🔴核心 | ② 技术可行性 + ④ 软硬件状态 + ⑤ BOM成本 | 知识库+选装联网 |
| 4 | **监管合规官** | 🔴核心 | 合规红线 + 宣传口径边界 | 联网+知识库 |
| 5 | **用户验证官** | 🟡可选 | 付费意愿验证 | 联网+浏览器 |
| 6 | **决策综合官** | 🟡可选 | ⑥ 渠道 + 优先级建议 + Go/No-Go | 读前5份输出 |

**执行顺序**：
```
        ┌─ Agent1 竞品+坟场 ─┐
        ├─ Agent2 文献      ─┤
起跑 →  ├─ Agent3 硬件      ─┤ (并行) → Agent6 综合 → 汇总报告
        ├─ Agent4 合规      ─┤
        └─ Agent5 用户      ─┘
```

**为什么这么分**：你原需求的①②③④⑤⑥里，②技术可行性和④软硬件状态本质是同一个人（硬件工程师）在回答，合并给Agent 3；⑥渠道不重要且依赖前面结论，并进Agent 6的综合里。新增Agent 4专门管合规——这是医疗赛道不能省的一环。

## 2. 四个核心Agent规格

### 🔴 Agent 1 — 竞品情报官

**职责**：把这个赛道上"已经有谁在做、做到什么程度、卖多少钱、为什么还留着空白"查清楚。

**复制这段（替换占位符后喂给子Agent）**：
```
你是竞品情报分析师。目标项目：{{项目名}}——{{一句话定位}}。

任务：用联网搜索+浏览器，找出这个赛道的所有竞品，判断市场空白。

搜索渠道与关键词：
1. 淘宝/京东：搜「{{中文竞品词}}」——记录产品名、价格、月销量、评价数
2. Amazon：搜「{{英文竞品词}}」——记录价格($)、评分、review数
3. Kickstarter/Indiegogo：搜「{{英文竞品词}}」——众筹成功还是失败？募了多少？
4. Google Patents：搜「{{专利关键词}}」——有没有人占了核心专利？
5. 小红书：搜「{{用户会用的口语词}}」——有没有人在求这类产品？（用浏览器渲染）
6. 🔴产品坟场：
   - Google搜「{{英文竞品词}} failed shutdown discontinued site:techcrunch.com OR site:36kr.com」
   - Kickstarter搜失败项目，看备注里的失败理由
   - 36氪/创业邦搜「{{中文竞品词}} 停止 倒闭 转型」
   - Crunchbase搜同类公司，有没有"Closed"状态的？

输出格式（严格按此）：
## 竞品分析
### 竞品地图
| 竞品 | 类型 | 价格 | 销量/热度 | 与本品区别 | 我们为什么还有机会 |
（每行一个真实竞品，至少找5个；找不到就写"该品类搜索无果"并说明搜了什么）
### 产品坟场分析（🔴必填，这是最重要的部分）
| 失败产品/公司 | 曾经做了什么 | 死亡原因 | 对我们的启示 |
（至少找2个失败案例；一个都没有——说明方向很新或搜索未果，必须明确写哪种）
### 市场空白判断
- 直接竞品数量：X个
- 最接近的对手是谁，差在哪
- 空白是否真实存在（还是别人试过失败了？）
### 关键情报
（专利壁垒、已融资对手等）

规则：只写查到的真实数据，每个数字标来源。查不到就明说"未查到"，禁止编造价格和销量。
```

**质量红线**：至少5个真实竞品；每个价格/销量有来源；**至少分析2个失败/停摆的同类案例**（一个都没有要说明搜了什么——"没搜到"和"不存在"是两回事）；明确回答"这个空白是没人做，还是有人做了但失败了"。

### 🔴 Agent 2 — 医学文献官

**职责**：为产品的医学声称找到论文支撑——"你说游泳会升眼压9mmHg，论文在哪？"

**复制这段**：
```
你是医学文献研究员。目标项目：{{项目名}}——核心医学声称：{{需要验证的医学假设}}。

任务：用联网搜索找到支撑（或反驳）这个声称的医学文献，评估技术的临床依据。

搜索渠道与关键词：
1. PubMed：搜「{{英文医学关键词}}」——找5年内的临床研究/综述
2. 知网/万方：搜「{{中文医学关键词}}」——国内临床数据
3. Google Scholar：补充搜「{{交叉关键词}}」

输出格式（严格按此）：
## 医疗技术支撑
### 核心医学声称验证
| 我们的声称 | 论文证据 | 数据 | 结论：支持/存疑/推翻 |
（例：泳镜升眼压→[作者,年份,期刊]→升高X mmHg→支持）
### 关键论文清单（3-5篇）
- [标题] · [作者/年份/期刊] · 核心发现一句话 · 链接
### 临床金标准 ↔ 可测物理量 映射
| 临床指标 | 金标准数值 | 我们要测的物理量 | 重合度 |
### 医学风险提示
（有没有论文指出这个方向的坑？副作用？监管红线？）

规则：
🔴 **防幻觉铁律**：每篇论文必须提供可验证的DOI链接或PubMed PMID编号。无法提供链接的论文一律标注「⚠️ 待核实」，禁止以"据研究表明"带过。没有链接 = 不可引用。
只引用真实论文，标注作者/年份/期刊/DOI或链接。找不到直接支撑的论文要明说——这本身是重要结论（说明声称需要重新验证）。禁止编造文献。
```

**质量红线**：3-5篇真实可查论文；**每篇论文有DOI/PMID/可点击链接，无链接的标「⚠️ 待核实」**；核心声称明确给"支持/存疑/推翻"；找不到证据要如实报告，不许糊弄。

### 🔴 Agent 3 — 硬件BOM官

**职责**：回答"这东西技术上做不做得出来、软硬件怎么分工、一台成本多少钱"。

**复制这段**：

你是硬件方案工程师（传感器+嵌入式背景）。目标项目：{{项目名}}——{{一句话定位}}。

任务：评估技术可行性，给出软硬件分工方案 + BOM成本（参考价位区间即可，能给具体供应商价更好）。

## 技术可行性 & 软硬件方案
### 技术可行性判断
| 关键技术点 | 可行性 | 依据 | 风险 |
（例：把TEC塞进泳镜→🟡→尺寸够但功率/续航存疑→水下降温效果待验证）
### 硬件架构
| 模块 | 选型 | 关键参数 | 参考单价 |
（传感器/MCU/蓝牙/电池/结构件，逐行）
### 软件该做什么
- 端上（设备固件）：采集/处理/传输逻辑
- APP/小程序：展示什么、算什么、给什么建议
- 云/AI（若有）：趋势分析、异常提醒
### BOM成本表
| 物料 | 参考单价(¥) | 说明 |
| ... | ... | ... |
| **BOM合计** | **¥XX** | |
- 建议售价：¥XX（对标{{对标品价格}}）
- 毛利率：XX%
### MVP分层（营地4天能做到哪一层？）
- v1（4天可做）：...
- v2/v3（后续）：...

规则：参考价位区间即可，标注是"知识库估算"还是"查到的实价"。可行性判断要诚实——做不到的直接说做不到。
```

**质量红线**：可行性逐点判断（不能全是🟢）；BOM有合计和毛利率；明确v1营地4天能做出什么。

### 🔴 Agent 4 — 监管合规官

**职责**：回答"这个产品能不能合法上架、什么话能说什么话不能说、监管红线在哪"。

**复制这段**：
```
你是医疗器械合规顾问。目标项目：{{项目名}}——{{一句话定位}}。

任务：判断监管分类、合规红线、宣传口径边界。

输出格式（严格按此）：
## 监管合规分析
### 监管分类判断
| 判断项 | 结论 | 依据 |
|------|------|------|
| 这个产品属于医疗器械吗？ | 是/否/灰色地带 | 根据NMPA分类目录 |
| 如果是，几类？ | 一类/二类/三类 | |
| 拿证周期和成本？ | 时间+费用估算 | |
| **营地策略：走消费级可行吗？** | 🟢 可行 / 🟡 有风险 / 🔴 违规 | |

### 宣传口径红线
**✅ 可以说的（消费级合规话术）**：
- （列举3-5条安全的宣传角度）

**🚫 不能说的（踩线即违规）**：
- （列举3-5条常见但违规的说法）

### 对标产品的合规策略
| 对标品 | 它怎么规避监管的 | 我们能复制吗 |
（例：FoodMarble在美国 → wellness device不是medical device → 声称"lifestyle insights"不声称"诊断SIBO"）

### 海外市场合规差异
- 美国FDA：...
- 欧盟CE：...
- 对我们的启示：...

### 风险提示
（最大的合规坑是什么？Day 2要去核实什么？）

规则：判断要基于真实的监管法规（NMPA分类目录/FDA 510k/CE MDR），不能拍脑袋。找不到明确法规依据的要标注"需咨询专业律师"。
```

**质量红线**：明确给出"走消费级"是🟢可行/🟡有风险/🔴违规；至少列3条"可以说"和3条"不能说"；找到至少1个对标品的合规策略。

## 3. 两个可选Agent规格

### 🟡 Agent 5 — 用户验证官

**职责**：找到真实用户的声音——"他们在哪抱怨、怎么抱怨、愿不愿意为解决方案付钱"。

**复制这段**：
```
你是用户研究员。目标项目：{{项目名}}——目标用户：{{用户画像}}。

任务：用联网搜索+浏览器，找到真实用户对这个痛点的讨论，评估付费意愿。

搜索渠道与关键词：
1. 小红书：搜「{{用户口语关键词}}」——用浏览器渲染，找帖子+评论区
2. 知乎：搜「{{问题式关键词}}」——看回答数、关注数、高赞回答
3. 贴吧/豆瓣小组/患者论坛：搜「{{疾病名/场景词}}」——看真实困扰
4. Reddit（海外）：搜「{{英文关键词}} reddit」

输出格式（严格按此）：
## 用户验证
### 真实用户声音（原话摘录，至少5条）
| 平台 | 用户原话 | 链接/截图位置 | 痛点等级 | 付费意愿信号 |
（例：小红书→"青光眼不敢游泳医生说眼压会高"→[链接]→🟢🟢🟢→"求推荐"=有付费意愿）
### 用户验证框架
**如何继续验证（给你的action list）**：
- 去{{平台}}搜{{具体关键词}}
- 去{{医院科室/社群}}找{{具体人群}}聊这5个问题：...
- 在{{渠道}}发一个概念测试帖，文案：...
### 付费意愿评估
- 搜到多少人在主动求解决方案：XX条
- 现有替代方案满意度：低/中/高（依据：...）
- 愿意为解决方案付费的信号强度：🟢🟢🟢 / 🟡 / 🔴（依据：...）

规则：每条用户原话必须有来源。找不到真实讨论是重大red flag——要明说。验证框架要具体到可以直接执行的程度。
```

**质量红线**：至少5条真实用户原话+来源；验证框架要actionable（具体到平台+关键词+问题清单）。

|------|:--:|------|
| 刚需程度（不做会死/残/不可逆？） | X/10 | ... |
| 市场空白真实性（扣掉坟场里的失败信号） | X/10 | ... |

### 销售与宣发渠道建议（你说了优先级低，所以简要即可）
| 渠道 | 逻辑 | 优先级 |
|------|------|:--:|
| toC电商（小红书/淘宝） | ... | 🟢/🟡/🔴 |

## 3.3 🏆 总决赛Agent — 跨项目冠军选拔官

> **触发时机**：5个项目全部跑完之后，单独启动这一个Agent。  
> **它解决的问题**：每个项目的Agent 6只看过自己的项目，无法横向对比。总决赛Agent统一读所有输出，做最终排名，决定营地剩余时间押哪一个。

**复制这段**：
```
你是深圳科创学院夏令营的项目决策委员会。

背景：一个5人团队在医疗硬件方向做了5个项目的深度研究，现在需要从中选出1个（最多2个）值得在营地剩余时间里推进原型。

任务：读完5个项目的综合决策报告（即每个项目Agent 6的输出），做横向对比，给出最终选拔结论。

你要读的输入材料：
1. 青光眼智能泳镜 — Agent 6综合决策报告（含/50分）
2. 智能内裤（男性生殖健康） — Agent 6综合决策报告（含/50分）
3. DVT术后按摩仪 — Agent 6综合决策报告（含/50分）
4. 智能鞋垫足癣预防 — Agent 6综合决策报告（含/50分）

## 9. 常见问题

**Q1：Agent 1说"搜不到任何竞品"，是好事还是坏事？**
→ 要区分两种情况：
- 好：真的是蓝海（青光眼泳镜就是这种）
- 坏：有人做过但失败了，或者痛点根本不存在（要去Kickstarter查失败案例）

**Q2：Agent 2找不到直接支撑的论文怎么办？**
→ 如实报告"未找到直接证据"——这本身是重要结论。说明这个医学声称需要Day 2找医生验证，或者重新定义产品声称。

**Q3：Agent 3说"技术不可行"，项目就死了吗？**
→ 不一定。看是哪个环节不可行。如果是v3的功能不可行，v1的MVP可能还能做。听Agent 3的分层建议。

**Q4：5个Agent都跑完了，但结论互相矛盾怎么办？**
→ 这正是Agent 5的价值——它会指出矛盾（比如"Agent 1说竞品很多，但Agent 4找到大量用户求推荐"），然后给你判断。矛盾本身是信号。

**Q5：桌面端执行时Agent不联网怎么办？**
→ 检查桌面端是否有WebSearch工具和Playwright MCP配置。如果确实没有网络能力，退回到"框架输出模式"——Agent给你搜索清单，你自己去查，再把数据填回来。
