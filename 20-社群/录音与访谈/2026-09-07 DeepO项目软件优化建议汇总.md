# DeepO 软件产品优化建议汇总

**来源：** 与工程师 娄泰袁葛 的聊天逐字稿  
**日期：** 2026-09-07  
**参与人：** 孙超（产品视角）、娄泰袁葛（光学工程师/在读博士）

---

## 一、用户定位与产品分层

### 1.1 非光学专业人员——定位：学习与架构理解工具
- **目标用户：** 摄影爱好者、激光器工程师（非镜头设计方向）、半业余人士
- **核心价值：** 通过自然语言交互，帮助用户快速了解光学基础知识、理解不同架构的效果差异
- **使用场景举例：**
  - 想知道广角镜头和长焦镜头的区别，但无法拆真实镜头 → 在工具中输入参数，可视化对比
  - 激光器工程师想做光束准直/扩束/整形 → 输入参数，工具给出大致镜片数量和布局建议
  - 非光学背景的产品经理 → 跟研发对接需求前，先在心里有个数，判断需求是否合理、大致架构走向

### 1.2 专业光学工程师——定位：初始结构生成 + 新架构探索
- **核心价值一：突破经验限制，探索前所未见的结构**
  - 可微分方法不依赖固定专利库模式，理论上能产出从未有过的镜头架构（如用 2 片镜完成传统 3 片镜的任务）
  - 这是 DeepO 相比传统软件的独特优势，也是其"巨大价值"所在
- **核心价值二：从专利库/镜头库中快速学习和收敛**
  - 大多数工程师不需要从头创立新架构，而是基于已有镜头快速找到符合指标的解
  - 工具应在"学习 + 收敛"环节提供显著效率提升

### 1.3 产品分层建议
- 针对两类用户设计不同的使用路径和功能侧重
- 非专业用户：降低门槛，强调交互体验和教育价值
- 专业用户：强调效率、结果质量、与现有工作流的兼容性

## 二、性能与效率要求

### 2.1 首半小时体验决定用户留存
- **核心原则：** 如果用户使用 30 分钟后感觉比 Zemax/Codex 效率更低，会立即放弃
- 自然语言交互本身不足以让用户容忍低效，性能必须跟上甚至超越传统工具
- 产品化的首要任务是保证前半小时的"爽感"

### 2.2 分阶段优化策略
不同优化阶段需要不同的策略组合：
- **前 0~50% 阶段（快速探索）：** 谁快谁准谁好就用谁
- **后段收敛阶段：** 需选用口碑分策略、Zemax 评价函数组合策略或其他可靠方法
- **产品建议：** DeepO 应明确自己在哪一阶段最具优势，并针对不同阶段提供差异化策略选择

### 2.3 GPU 加速的长期潜力
- 当前商用软件（Zemax 等）主要运行在 CPU/内存上
- DeepO 的可微分方法天然适合 GPU 并行训练
- 随着显卡发展，理论上 DeepO 的运算速度有可能超越传统商用软件
- **建议：** 在产品规划中预留 GPU 加速架构，为未来性能跃升做准备

## 三、核心功能优化建议

### 3.1 初始结构生成——主打功能
- **定位：** 目前最可行的产品化切入点
- **优化方向：**
  - 输入一组指标参数，快速输出一个合理的初始结构
  - 初始结构可以不完全 optimal，但必须是"可用的起点"
  - 建议用训练集方法完成 5%~10% 的工作，再用可微分优化方法完成剩余部分

### 3.2 自然语言交互——核心差异化优势
- **现状：** 这是 DeepO 相比传统软件最突出的优势
- **优化方向：**
  - 持续打磨 NLP 理解能力，确保用户的自然语言描述能被准确转化为光学参数
  - 支持更丰富的自然语言输入形式（模糊描述、场景描述、对比描述等）
  - 注意：自然语言是入口，但输出质量必须过硬，否则用户仍会转向传统工具

### 3.3 评价函数体系——专业用户的关键需求
- **问题：** 当前优化主要依赖点列图作为损失函数，但专业工程师有自己的评价体系
- **优化方向：**
  - 引入可配置的评价函数体系，允许专业用户自定义优化目标
  - 原子化封装各种光学评价指标（MTF、畸变、像散等），供用户灵活组合
  - 参考 Zemax 评价函数体系，提供类似的自定义能力

### 3.4 Code V 兼容性——重要的行业壁垒
- **建议：** 支持 Code V 2026 的选型和文件导入/导出
- 如果能直接处理 Code V 文件，将大幅降低专业用户的迁移成本
- 这是 DeepO 进入专业工作流的关键功能之一

## 四、数据与训练策略

### 4.1 训练数据集建设
- **数据来源优先级：**
  1. 百万级镜头库（雨桐已提供的资源）
  2. 开源专利库（自动下载 + OCR 识别）
  3. 闭源专业镜头库（Code V 等）
  4. 团队自有的设计经验数据
- **数据清洗要求：**
  - 对输入数据进行分类和筛选
  - 处理部分缺失的输入和噪声输入
  - 建立输入-输出对的标准化格式

### 4.2 自动化数据采集 Pipeline
- **构想：** 自动下载专利 → OCR 识别 → 提取镜头参数 → 自动生成 Zemax 文件 → 转化为训练语料
- **输出格式：** Excel 或结构化文件，包含指标参数和对应的镜头结构
- **意义：** 解决训练数据瓶颈，同时为后续迭代提供持续的数据来源

### 4.3 数据标注策略
- 可用可微分方法生成更多参数组合的初始结构，自主构建专利库
- 通过参数变化产生大量"输入-输出"对，用于训练模型

## 五、工作流集成

### 5.1 API 集成方案
- **最低可行方案：** 将 DeepO 作为 API 接入 Zemax
- 用户无需离开熟悉的工作环境，通过 API 调用 DeepO 的初始结构生成能力
- 这比要求用户完全切换工具更现实

### 5.2 与现有工具的协作关系
- DeepO 不应试图替代 Zemax/Codex 的全流程
- 明确定位为"初始结构生成器"或"架构探索工具"
- 与现有工具形成互补：DeepO 负责"从 0 到 1"的架构生成，Zemax/Codex 负责后续精细优化

## 六、产品化路径建议

### 6.1 MVP 阶段（0→1）
- **核心目标：** 前 30 分钟体验优于传统工具
- **关键功能：**
  1. 自然语言输入 → 初始结构输出
  2. 基础的镜头可视化展示
  3. 训练集驱动的快速结构生成（占 5%~10% 工作量）
- **数据来源：** 先用已有的镜头库数据完成初步训练

### 6.2 成长阶段（1→10）
- 逐步引入可微分优化方法，提升结构质量
- 建设自动化数据采集 Pipeline，扩大训练数据规模
- 添加 Code V 兼容性
- 引入评价函数自定义能力

### 6.3 成熟阶段（10→N）
- GPU 加速全面上线，性能超越传统工具
- 形成完整的"自然语言→初始结构→精细优化"工作流
- 建立专利库自主生成能力
