# V1.1 开发规格

## 1. 目标

将《个人工作流自动化系统 V1.1》先落地为一个可运行、可验证、可继续迭代的最小实现。

## 2. 设计原则

- 规则大于系统
- 信息单向流动
- 单一归属
- 所有重要操作先二次确认
- V1.1 只做高频重复动作，不做复杂编排

## 3. 当前最小实现

### 3.1 已落地模块

1. `workflow.config.json`
   - 固化版本号、提醒时间、分类、确认规则、保留天数
2. `convert-ai-chat.mjs`
   - 负责 AI 对话导出 JSON -> Markdown
3. `organize-work-fragments.mjs`
   - 负责把一批工作碎片整理成结构化 Markdown
4. `render-workflow-message.mjs`
   - 负责统一生成确认文案与执行结果文案

### 3.2 暂不实现

- 直接写入飞书云文档
- 直接写入 Obsidian 指定文件
- 直接写入 IMA
- 自动删除真实业务文件
- 无确认前的自动执行

## 4. 数据模型（建议）

### 4.1 Item

- `id`
- `source`: `wechat | file | ai_export | manual`
- `category`: `inbox | todo | fragment | temp | idea`
- `status`: `pending | waiting_confirm | confirmed | cancelled | done`
- `target`: `feishu_doc | obsidian | ima | calendar | return_only`
- `created_at`
- `expires_at`
- `need_confirmation`

### 4.2 ReminderRule

- `id`
- `owner`: `qclaw | codex`
- `type`: `daily | every_3_days | weekly | biweekly | quarterly | monthly`
- `time`
- `enabled`
- `message`

### 4.3 OperationLog

- `id`
- `task_name`
- `operator`
- `action`
- `result`
- `confirmed_by_user`
- `created_at`

## 5. 建议迭代顺序

### Phase 1（本次已开始）

- 固化规则
- 做转换器
- 做整理器
- 做确认文案生成器

### Phase 2

- 接一层轻量日志
- 接一层真实提醒输入
- 接一层待分拣数据结构

### Phase 3

- 基于你的真实样本调优 JSON 解析规则
- 增加月报生成
- 增加任务状态回写

## 6. 验收方式

运行：

```bash
npm run test:samples
```

验收标准：

- 能生成 AI 对话 Markdown
- 能生成工作碎片整理 Markdown
- 能生成标准结果文案
- 所有输出均不绕过二次确认
