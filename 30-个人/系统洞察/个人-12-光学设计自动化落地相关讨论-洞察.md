## 技术知识

### 🔖 [技术知识] 光学设计自动化全流程拆解：八大环节与可行性分层

对话完整拆解了一家做眼科 OCT/眼底相机的公司光学设计流程，并给每一步的自动化可行性打了分。全流程八环：需求指标分解 → 初始架构选择 → 范式（CodeV）优化 → 权重分析/结果排序 → 光机结合与杂散光分析 → 壳体/热设计 → 装配迭代 → 性能检测合格 → 小批量生产。自动化可行性由高到低分层明确：初始架构选择最可行（选型库 + 打分系统即可自动化）；优化策略蒸馏难度最高（专家逻辑判断不可言说）；光机结合涉及 3D 建模 + 软件 API + Python 脚本，"涉及空间的 3D 建模……你想变成一个泛用的脚本的话那就更复杂了"，被一致判定为"这个地方我建议不要去折腾"；端到端全自动"就极限就这个样子""最接近就是初始结构，没有其他东西了"。耗时卡点在优化迭代环节（如 130 度到 150 度视场变更这类反复改架构），而自动化能做的只是"加速"而非"突破"——"突破是突，感觉突破不了"，10 万工程师是 10 万的水平、20 万是 20 万的水平，专家又快又准又省时间，你花多少成本就摆在这个地方。因果链：光学设计链条长且多环节靠个人经验 → 各环节自动化成本/收益差异巨大 → 只有把经验沉淀成规则的初始选型值得先做，其余只能长期打磨。

### 🔖 [技术知识] 优化策略必须「原子化」：把判断逻辑拆成可自由组合的最小单元

对"怎么把专家优化策略蒸馏出来"给出了方法论级答案——原子化。每个操作判断逻辑（看到这张图/这个指标变化就知道下一步怎么做）必须拆成原子单元，然后自由组合成多个优化逻辑；"不原子化就不行，不然的话你给了一大坨，这个东西不符合逻辑的"，策略本质上就是一长串判断逻辑通过组合方式拼起来的。这是蒸馏过程中最难、也最值钱的一部分——"就是这种方法，要把每一个判断逻辑……看到这张图，我就知道下一步应该怎么做，就这么简单"。要有一个专家配合你搞这个，"你相当于不就把专家给蒸馏出来了，那值很多钱了"。投入周期是月级甚至半年级的，但趋势确定——"这个东西你搞一年两年肯定没问题的，反正这就是趋势，五年之内这个东西必须是有一个人能做出来"，而且大概率是 Zmax 自己做，独立玩家只能"打个时间差"，因为最后建的所有东西都站在他的软件之上。

### 🔖 [技术知识] 初始架构选型自动化：最接近落地的一步（打分 + 知识库 + 低门槛入口）

这是全场四人最终收敛的唯一"马上能做成"的点。现状：指标不同对应好几种默认架构，工程师靠记忆力和树状目录手动找。自动化方案闭环：第一步把市面所有可用的专利参数、以前公司所有镜头库、迭代优化中没用上的优秀案例沉淀成自用知识库；第二步"表格输入加大模型"——在飞书多维表格里输入焦距/口径/F数/材料/片数/架构几个数字，调用知识库按分权重打分选型（"分权重打分选型……会得到匹配一、匹配二、匹配三、匹配四、匹配五"）；第三步多个优秀初始架构并列跑优化（"以前是一个人只能跑一个案例，晚上回家之后就跑不了，现在让他没日没夜的跑，一直把电脑的性能压干、榨干为止"）。权重从哪来：定义者是甲方工程师，要问"为什么你觉得这个镜头好那个镜头不好"，把隐性判断量化成 0.8 还是 0.9。技术栈就是常规 RAG 向量化知识库管理 + 数据清洗 + 选型约束规则。判断依据必须标准化可追溯（"我选择这玩意就是因为这个原因"），否则黑盒不稳定性就是工程风险。已有商品化对标：智象光学软件，30 天 40 元，做初始架构选型和自动化设计。

### 🔖 [技术知识] AI 写 Zmax 宏的瓶颈在训练语料：不是模型版本问题

Zmax 宏语言本身是"非常标准化的一个程序"，是小的原子化优化策略，理论上最适合用 Codex 生成。但现场两次实测（Claude 与 DeepSeek 各写一版）全部语法报错跑不起来；早前 OPUS 4.6 也写过，写不出来——"它素材太少了""跟它训练语料库有关系，就是它的资料太少"，结论是 5.6 大概率也不行，问题不在模型版本而在垂类语料缺失。即使勉强跑通，还面临迭代无底洞："他们写出来之后，我们要测试，测试效果不好，我们继续迭代，继续测试，继续迭代，它是一个无底洞"。替代路线有三条：MCP 直连 Zmax（能连上，但"拍 ZDD 是可以跑，但是他不会把报错弄出来"，报错信息不回传，交互有黑盒）；写 Python 外部扩展程序（读不到软件内部界面的数据）；以及退而求其次让工程师自己尝试用 Codex 写宏——但"他们不会用，就算会用，他们也不会去用，不配合"。矛盾点：宏对工程师价值极高（"点一下宏，什么报告都出来了，什么参数都出来了"，工程师对能写宏的人信任且尊敬），但 AI 生成路线目前被语料卡死。

## 行业洞察

### 🔖 [行业洞察] 蒸馏光学专家优化技巧：最难也最值钱的行业壁垒

核心论述：光学工程师的优化技巧是一套"逻辑判断反馈"的循环——看到参数判断哪里不行、做调整、看反馈再判断，这个判断过程"没法写下来""人家很难跟你说"。要蒸馏出它只有三种路径：第一种是五感追踪——录屏或用软件脚本追踪专家操作，Codephile 自带脚本追踪功能，"你每天都干了什么，干了什么，它都会多一行"，跟踪一两周、让他从初始架构跑到目标架构多跑几个模型，就能把判断依据学出来；第二种是交互推断——看专家每步操作并追问为什么；第三种是专家自述——能讲清楚自己的判断逻辑。方法论判断：这不是难不难的问题，是行业壁垒本身——"你能把把这个东西给搞定，我们普通光学工程师都可以下岗了，初级光学工程师就可以下岗了"，而这个做出来价值"百万以上""几百万"。信息差结论：垂直行业里干十几年、有众多量产经验的产品专家，其知识"在网上是获取不到的，你没办法通过广义的获取能获取到，你只有跟他们去聊"，泛用大模型（GPT）问了也不会——"他们已经超出泛用大模型的那种概念了"。所以"专业人员蒸馏专业人员这件事情本身就有巨大市场价值，但同时也非常困难"。

## 创业认知

### 🔖 [创业认知] 企业 AI 落地服务是「无底洞」：非标不可复制，只做可标准化切片

对话对"做 FDE/帮企业做 AI 知识库转型"这类生意做了一票否决式判断，同时给出唯一可行的切片。否决逻辑：知识库、AI 转型落地本质是"无底洞激励的东西"——"它是个非标的东西，它非标的东西它会无限加需求，它会出错，它就不能实现复制跟裂变，就不符合创业跟商业化的性质"。佐证：FDE 模式在光电行业没看到有人做成（"在光电里面没有看到，但是在其他行业是有人做成"），而接触过的 FDE/FDA"也苦的要死"；端到端完全解决客户问题不可能，"优化策略都很难搞出来的"。唯一可标准化的切片是初始结构选型。落地姿势三种：一是做解决方案商/中介——不自己干重活，"专业的事情交给专业的厂商……你就拿分佣就好了"，对接软件负责人、把可实现结果和预期给到客户公司、中间抽成 30%，"你只需要做一个拉通对齐的功能就好了"，客户入口在你手上就收入口费、交付交给别人；二是做轻量 skill 接 Codex 给客户，但要警惕黑盒风险——"你不能保证它能稳定的产出且可靠的东西……它有时候有用，有时候没有用……这就是很大的一个工程风险"，客户"不能稳定产出就不会用你的"；三是长期做产品化，单项目不划算但多做几个项目很划算——"产品化是很有价值……这些东西都是他们的核心中的核心"，但那是工业软件量级的长期生意。
