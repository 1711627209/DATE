### 🔖 [技术成本] 多模型分级调度：简单任务免费，复杂任务付费（完整方法）
对话揭示了当前最经济的多模型调度策略：用 Agnes（免费或极低价格）处理日常简单任务，用 DeepSeek V4 Flash 处理复杂推理，用 GLM 5.3 作为中间层补充。核心逻辑：一个任务可以被拆解成不同难度级别——规划类、方案设计类、执行类各分配给不同模型，用提示词工程把 token 消耗降到最低。D哥实测：用提示词约束让 DeepSeek 在高峰期一个任务从 80 积分降到 8 积分，省 10 倍且效果不差。配套参考：腾讯内部工程师一个月 1500 元 token 预算，用混元大模型已经够用，没必要买最好的。

### 🔖 [技术成本] 创业前必须做"API成本管理"：不是抠门，是聪明（完整论述）
D哥的核心判断：创业之前就要把 API 成本体系搭好，否则一个月 token 费用差几千到上万。具体方法：① 用 Workbuddy 包月（70 元/月，4000 积分）替代单独买 DeepSeek API；② 用免费模型（Agnes + 腾讯混元 + NVIDIA 55B）覆盖日常 2.7 亿 token/天的免费额度；③ 只有确实需要高质量输出的任务才用付费模型，且用提示词工程压到最低。D哥观点："我觉得这不是因为我穷，而是因为我聪明"。

### 🔖 [创业认知] Agent 架构设计：LLM 本身不能上网，必须配工具才能联网探索（完整论述）
D哥通过拷打 DeepSeek 搞清楚了一个重要架构问题：LLM 离线后知识冻结，联网的唯一方式是给它配工具（web fetch、skill）。Genius 平台上的模型全是生成类，没有搜索端点，所以不能直接联网。正确做法是：DeepSeek 作为"机甲驾驶员"，把 API 放到平台里，让它调用本地各种 skill 去互联网上获取信息。D哥原话："公司能不能上网，不是他手里有没有模型，而是他手里有没有工具"。

### 🔖 [技术知识] GLM 5.3 Flash 是 DeepSeek 同类产品的最佳替代窗口（完整论述）
D哥发现一个套利机会：智谱 GLM 5.3 Flash 与 DeepSeek 当时第一轮产品发布时的策略几乎一样——先通过黑客松赠送大量免费 token 吸引用户，再转为收费。D哥建议"赶紧抓住这轮"，并且提到数字生命卡兹克已经写过分析文章。同时，D哥实测 OpenRouter 的 GLM 5.3 Flash，花 4 块钱就完成了以往 DeepSeek 要 77 块才能完成的量级，而且免费模型（Agnes）生图质量和 V4 几乎一样甚至更好。

### 🔖 [技术成本] 提示词工程可以压 10 倍 token：高峰期任务约束法（完整方法）
D哥提出一个具体可操作的方法：在提示词中明确约束模型的 token 使用，比如"非必要情况下不使用 DeepSeek，其他情况全部使用 Agnes"，高峰期一个任务从 80 credit 压到 8 credit，省 10 倍且效果不打折。配套策略：复杂任务拆分为 planner（规划）→ designer（方案设计）→ user（执行）三个角色，分别分配给不同便宜模型，只有最终整合时才用付费模型。
> 来源：AI模型调用与成本优化逐字稿 · 00:01-00:03, 00:50-00:52

### 🔖 [创业认知] 大厂员工创业铁律失败的原因：不知道控制成本（完整论述）
D哥给出一个反直觉判断：大厂员工创业几乎必然失败。原因：大厂里电脑、API、工具全部配最好的，月薪七八万，请程序员三四万，根本不知道什么是成本控制。他们创业后依然烧最好的 token、租大办公室，一两年烧完回去上班，发现回不去了。唯一例外是"天才员工"——这种人本身就不应该上班，去大厂只是混文凭。D哥建议：想理解创业成本，先去路边摆个摊亏 100 块，就会明白创业的滋味。

### 🔖 [创业认知] 不重复造轮子：把 PDF 文档喂给 Codex 让它自己搭建（完整方法）
D哥分享了一个具体实践：把 DeepSeek Harness 白皮书 + 黑客松方案 + 数字生命卡兹克的文章三份文件同时喂给 Codex，让它自己去部署。孙超的策略是"自己搭"，D哥认为让 Codex 前期搭建更高效，因为自己在迭代过程中会卡 bug，需要反复修复（花了 30 分钟到 1.5 小时）。核心判断：能外包的外包出去，不要自己熬夜做所有事情。

### 🔖 [技术成本] Agent 调用分层比例反常识：定义了 N 个 Agent ≠ N 倍分流（完整论述）
定义了 N 个 Agent（Genius 平台），理论上 Agent 层调用次数应比底层模型（DeepSeek）高 N 倍以上；但实测 DeepSeek 1200+ 次 vs Genius 300+ 次，比例严重倒挂。这说明 Agent 架构设计并未真正发挥"分流"作用——模型调用直接穿透了 Agent 层。纯靠"定义层级"不够，需要配合关键词/Prompt 指令工程强制分流，否则 Agent 架构只是摆设。这是孙超和张鹏博共同发现的系统性问题，也是后续要求调整"非必要不使用 DeepSeek"指令的原因。
> 来源：2026-08-27 AI模型调用与成本优化讨论 逐字稿 · 00:02:11-00:03:15

### 🔖 [创业认知] 故障修复日志即资产：解决一次问题变成可复用公共方案（完整方法）
孙超提出的关键原则：每次解决 Harness 平台的 bug 后，要把维修日志整理成文档上传到 Git，使其成为可复用的公共解决方案。核心思维是把"解决一次问题"转化为"产生一个资产"，避免团队/社区重复踩同一个坑。张鹏博的反应："沉淀这个思维很强，我根本想不到这一点"。这套思路延伸到更广泛的工程实践：任何故障修复都应该产出可检索的文档，形成知识库的增量。

### 🔖 [行业洞察] 潮州商人思维：AI 在他们面前是发财玩具，不靠 AI 发财（完整论述）
与潮州商人打交道的核心洞察：他们的全是做生意的，吃饭都在聊谁又挣几千万、谁又财富自由。对他们而言 AI 只是一个发财的玩具而已，他们不靠 AI 发财——AI 在他们手上是工具，不是信仰。这对比技术出身的人形成鲜明反差：技术人容易把 AI 当成核心能力来构建，而商人只关心它能带来什么实际的商业价值。这套思维模式的核心是务实：不崇拜工具，只问结果。
