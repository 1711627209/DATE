## 技术成本

🧷 **[敏锐关键词] API 调用分层比例反常识**
**是什么：** 定义了 N 个 Agent（Genius 平台），理论上 Agent 层调用次数应比底层模型（DeepSeek）高 N 倍以上；但实测 DeepSeek 1200+ 次 vs Genius 300+ 次，比例倒挂。
**为什么值得注意：** 这说明 Agent 架构设计并未真正发挥"分流"作用——模型调用直接穿透了 Agent 层。不是简单的"调用多了"，而是架构本身有漏洞，20+ Agent 没有产生 20+ 倍的调用增益。

🧷 **[敏锐关键词] 提示词约束法压 10 倍 token**
**是什么：** 在系统提示词中加入"非必要情况下不使用 DeepSeek，其他情况全部使用 Agnes"的明确指令，可让高峰期单任务消耗从 80 credit 压到 8 credit，效果不降级。
**为什么值得注意：** 这不是泛泛的"优化提示词"，而是一个具体的、可复制的操作参数——一条指令换来 10 倍成本节约。核心原理是模型服从系统性约束而非逐条判断。

🧷 **[敏锐关键词] Agent 分流失效：结构 vs 指令**
**是什么：** 即使定义了 20 多个 Agent，DeepSeek 调用量仍远高于 Agent 层，说明纯靠"定义层级"不够，需要配合关键词/指令工程强制分流。
**为什么值得注意：** 普遍认知是"Agent 多了自然分流"，但这是错的。Agent 架构只是提供了分流的可能性，真正实现分流需要显式的 Prompt 约束——这是一个容易被忽视的工程细节。

**是什么：** Claude 的上下文窗口更长，适合长对话和复杂任务场景；DeepSeek 在图片生成类任务上有独特优势。

🧷 **[敏锐关键词] 多模型分级调度的三层架构**
**是什么：** 用三层模型分工覆盖不同任务难度：简单任务→Agnes（免费），复杂推理→DeepSeek V4 Flash（付费），中间补充→GLM 5.3。
**为什么值得注意：** 这是一种可复用的成本控制框架，核心原则是"按任务难度分层定价"，而非"全部用最贵的"或"全部用最便宜的"。GLM 5.3 的发现更是利用了厂商推广期的免费窗口进行套利。

## 技术成本

🧷 **[敏锐关键词] 国中之国（自己的 OPC）**
**是什么：** 指完全自建、自主可控的 AI 基础设施体系——包括自搭的 Harness 平台、Agent 架构、工具链，不依赖第三方 SaaS 的封闭系统。
**为什么值得注意：** 这是孙超提出的核心概念，代表一种架构哲学：与其被供应商绑定，不如自建基础设施，即使初期不稳定、有 bug，长期看是最可控、成本最低的路径。

🧷 **[敏锐关键词] 机甲驾驶员比喻**
**是什么：** LLM 是驾驶员，电脑/平台是机甲——把 DeepSeek API 放进 Cloud 环境，配合各种工具（web fetch、文件读写），机甲就能联网、能干各种事。
**为什么值得注意：** 这个比喻精准解释了 LLM 能力边界和 Agent 架构本质：模型本身不会上网，联网靠的是工具链，模型只是"大脑"。理解了这一点就能正确设计 Agent 系统。

🧷 **[敏锐关键词] 以量取胜**
**是什么：** 不用搜索 API（付费、有限制），而是靠 Agent 批量公开检索公众号等公开内容，零验证码、零登录、零计费，用数量弥补质量损失。

## 创业认知

🧷 **[敏锐关键词] 奴隶主思维**
**是什么：** 把 AI 当作下属来"拷打"——不断追问、验证、逼迫其给出正确答案，而非被动接受输出。
**为什么值得注意：** 高阶 AI 使用姿势：把 AI 当工具而非权威，用质疑和验证来确保输出质量。张鹏博原话："跟超哥学的，咱们两个现在就跟奴隶主一样"。
